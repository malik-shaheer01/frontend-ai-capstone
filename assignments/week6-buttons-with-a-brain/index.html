Duration & easing notes

Hover/focus (150ms, ease-out): fast enough to feel like direct response to the cursor, ease-out so the lift settles rather than overshooting.

Press (80ms, ease-in): shorter than hover on purpose — a physical press reads as instant, and ease-in gives it a quick "give" rather than a bounce.

Idle ↔ loading crossfade (220ms, standard ease-in-out): long enough to read as deliberate ("this has started/finished"), short enough not to feel laggy.

Loading → success (200ms, back/pop ease): a small overshoot on the checkmark reads as a tiny confirmation without being cartoonish, then holds 900ms before crossfading back to idle.

Loading → error (350ms shake): a single shake communicates "no" viscerally and finishes fast so the button never feels stuck; color and a retry label carry the rest of the message.

Width is fixed, never animated — every state lives in an absolutely-positioned layer crossfaded with opacity/transform only, so nothing here ever triggers layout (no reflow-driven jank, compositor-only animations).

Reduced motion: under prefers-reduced-motion: reduce, all transform/animation is dropped except the spinner's spin (it is the feedback that work is happening, not decoration) — crossfades still happen, just near-instant, so state changes stay visible.
